# 시스템 전수 검토

문장 내용이 아니라 **코드 구조와 로직**을 대상으로 점검했습니다.
실제로 실행해 재현한 것만 적었습니다.

---

## A. 지금 고쳐야 할 오류

### A-1. 통계 화면이 깨진다 ★ 심각

**재현** — 해석 가림 모드에서 한 문제를 틀린 뒤 「백업」을 연다.

```
TypeError: Cannot read properties of undefined (reading 't')
→ 통계 화면이 통째로 비어버린다
```

**원인** — 통계를 저장하는 키가 모드마다 다릅니다.

```
일본어 쪽 문제   키 = "watashi"       → WORDS["watashi"] 있음
한국어 쪽 문제   키 = "ko:저"          → WORDS["ko:저"] 없음 → undefined.t 접근
```

통계 화면은 모든 키를 사전에서 찾으려 해서 한국어 키를 만나면 멈춥니다.

**부수 문제** — 같은 단어인데 모드별로 기록이 따로 쌓입니다. `私`를 일본어 쪽에서 3번, 한국어 쪽에서 2번 틀려도 「5번 틀림」으로 합쳐지지 않습니다.

---

### A-2. 팝업이 겹쳐 열린다

**재현** — 툴팁을 연 채로 가려진 단어를 누른다.

```
툴팁 열림 → 퀴즈 열기 → 둘 다 열려 있음
퀴즈 열림 → 모드 메뉴 → 둘 다 열려 있음
모드 열림 → 백업     → 둘 다 열려 있음
```

**원인** — 각 팝업이 자기만 열고, 다른 팝업을 닫지 않습니다. 뒤 배경(`bd`)은 하나뿐이라 한 번 누르면 전부 닫히지만, **열 때 서로를 정리하지 않습니다.**

화면이 좁은 폰에서 팝업 두 개가 겹치면 조작이 꼬입니다.

---

### A-3. 맞힌 문제가 되살아난다

**재현** — 문제를 맞힌 뒤 모드를 바꿨다가 되돌아온다.

```
맞힌 뒤        마스크 224개
모드 왕복 뒤   마스크 225개  ← 맞힌 것이 다시 가려짐
```

**원인** — 맞힘 표시가 DOM에만 있고 저장되지 않습니다. `build()`가 화면을 새로 그리면 사라집니다.

단계를 옮겼다 돌아와도 마찬가지입니다. 한 화면 안에서만 유지됩니다.

---

## B. 구조상 개선하면 좋은 것

### B-1. 진도 백업에 퀴즈 기록이 빠져 있다

백업 코드는 「어디까지 봤는지」만 담습니다.

```
J2|1||     ← 단계·완료·북마크만
```

**기기를 옮기면 퀴즈 통계가 사라집니다.** 어떤 단어를 자주 틀리는지가 이 앱의 학습 가치 중 하나인데 이동 수단이 없습니다.

다만 통계는 진도보다 데이터가 크므로 같은 코드에 넣으면 길어집니다. **별도 코드로 나누는 편**이 낫습니다.

---

### B-2. 「동작」 그룹이 375개로 지나치게 크다

```
동작 375  상태 190  이동 85  성질 73  장소 68 …  나라 4
```

그룹이 이만큼 크면 **같은 그룹이라는 것이 변별력을 주지 못합니다.** 동사 문제의 보기가 사실상 무작위에 가까워집니다.

동작을 몇 갈래로 나눌 필요가 있습니다.

```
동작 → 손동작 · 말하기 · 사고 · 사무 · 준비 · 매매
```

반대로 「나라」는 4개뿐이라 보기를 못 채워 품사 풀로 넘어갑니다. **6개 미만인 그룹은 사실상 작동하지 않습니다.**

```
나라 4   접속 7   가족 8   인명 9   옷 9   음료 10
```

---

### B-3. 정답 판정 기준이 여러 갈래로 흩어져 있다

지금 정답으로 인정되는 경로가 넷입니다.

```
1. 보기 값 == 정답
2. 보기 값 == 원래 표기 (조사 은/는 처리)
3. 같은 뜻 짝 (일본어 모드)
4. 같은 뜻 짝 (한국어 모드, 뜻 역추적)
```

동작은 하지만 조건이 한 곳에 뭉쳐 있어 앞으로 규칙을 더하면 얽히기 쉽습니다. **판정 함수 하나로 분리**하는 편이 안전합니다.

---

### B-4. 매번 50문장을 다시 그린다

모드를 바꾸거나 단계를 옮길 때마다 `build()`가 전체를 새로 만듭니다. 문장 50개에 단어 300여 개라 폰에서 한 박자 느립니다.

지금은 견딜 만하지만, 3,000문장이 다 차고 한 화면에 더 많은 정보가 붙으면 체감이 커집니다.

---

### B-5. 0단계 상태가 저장되지 않는다

가나 표를 보다가 앱을 닫으면 다음에 1단계로 돌아옵니다. 진도 저장 구조가 1~60단계만 상정하고 있습니다.

사소하지만 가나 표를 자주 볼 초기에는 걸립니다.

## D. 처리 순서 제안

**먼저 (오류)**

1. A-1 통계 화면 오류 — 키를 단어 기준으로 통일
2. A-2 팝업 겹침 — 열 때 다른 팝업을 닫는다
3. A-3 맞힘 표시 유지 — 저장하고 다시 그릴 때 반영

**다음 (구조)**

4. B-2 그룹 재편 — 동작 쪼개고, 작은 그룹은 합치거나 단어를 늘린다
5. B-3 판정 함수 분리
6. B-1 퀴즈 기록 백업

**나중에**

7. B-4 부분 렌더링 — 3,000문장이 다 찬 뒤 체감되면
8. B-5 0단계 저장

## E. 판단이 필요한 것

**맞힘 표시를 어디까지 남길 것인가**

- 한 화면 안에서만 (지금)
- 앱을 닫아도 유지 — 한 번 맞힌 문제는 계속 열린 채로
- 일정 시간 뒤 초기화 — 복습을 유도

두 번째는 편하지만 **다시 풀 기회가 사라집니다.** 세 번째가 학습에는 맞지만 구현이 복잡합니다.

지금은 첫 번째를 유지하되 **「이 단계 다시 풀기」 버튼**을 두는 정도가 적당해 보입니다.
