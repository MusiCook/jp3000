## C. 품질을 지키는 장치

### C-1. 보기 품질을 사람 눈 말고 기계로 ★★★

**먼저 읽을 것 — 지표를 목표로 삼지 말 것** (2026-09-15, 시제품으로 확인)

일회용 시제품을 돌린 결과다. 전체 9,225문제, 찍으면 25%.

| 전략 | 일본어 | 뜻 |
|---|---|---|
| 가장 흔한 앞말 | **23.7%** | - |
| 첫째 칸 | 23.5% | 24.6% |
| 가장 짧은 것 | 34.1% | **39.7%** |
| 남들과 가장 닮은 것 | 30.9% | **39.3%** |

- **2×2 는 완벽히 통했다** — 「가장 흔한 앞말」이 찍는 것과 같아졌다
- 「가장 짧은 것」이 뜻·서술에서 75.2% 로 튀기에 오답을 다른 낱말로 바꾸자고
  했는데, **파보니 둘 다 틀렸다.** 정답이 기본형인 비율은 서술 44.1% ·
  동사 38.9% · 형용사 44.2% 뿐이라 사람이 익힐 버릇이 못 된다. 짧은 것은
  말뭉치가 아니라 `endingAlts()` 가 만드는 부산물이고, 어미를 더하면
  길어지니 피할 수 없다. 게다가 고치려던 방법(`입니다` → `합니다`)은
  **길이를 재야 걸리던 것을 문장에 넣자마자 어색해서 걸리게** 만든다

**그래서 뜻·서술 보기는 그대로 둔다.** 지금이 옳다.

> **규칙 — 이 도구의 숫자는 답이 아니라 가설이다.**
> 높게 나온 전략은 눈으로 까 보고, 사람이 실제로 쓸 수 있는 단서인지
> 확인한 뒤에만 손댄다. 숫자를 낮추는 것 자체를 목표로 삼으면 멀쩡한
> 문제를 망친다. **이 규칙이 도구보다 중요하다.**

**할 일** — 시제품을 `tools/naive.js` 로 앉힌다. `check.js`·`quiz-audit.js`
옆에 두면 보기 규칙을 건드릴 때마다 회귀가 숫자로 잡힌다. 남은 32단계에서
같은 부류의 버그가 또 나올 걱정에 대한 답이기도 하다.

**아직 안 까 본 것** — `일본어 · 낱말 하나`(2,386문제)가 짧은 것 37.4% ·
닮은 것 41.5%. 위 규칙대로 **먼저 눈으로 봐야** 한다.

**보류 — 보기를 6개로 늘릴까**
재료는 3×2·2×3 모두 1,620/1,620(100%) 나오므로 **할 수 있느냐가 아니라 할
값어치가 있느냐**의 문제다. 폰에서 스크롤이 생기고 읽을 양이 1.5배가 되는데,
2×2 뒤로는 찍기 자체가 어려워져 이득이 얼마나 남는지 모른다.
**`tools/naive.js` 로 재고 정한다.** 2×2 는 2×3 의 부분집합이라 늘려도
지금 작업은 버려지지 않는다.

발음을 판정하지 않는다. 목표가 「여행에서 말하기」인데 **입이 빠져 있다.**

### E-2. 파일을 나눌 것인가
근거를 확정했다. 배포본 `dist/jp3000.html` 이 지금 **656,754 bytes(641 KB)**.

사전이 함께 느는 것을 빼도 **배포본이 0.9 MB 를 넘는다.**
*(`build.py` 가 찍는 495,208 은 바이트가 아니라 문자 수다. UTF-8 에서
한글·한자는 3바이트라 실제 파일이 더 크다.)*

### E-3. 진도 자동 동기화
지금은 Firebase 로그인 아니면 코드 복사. 서버를 붙일지.

한 화면 안에서만(지금) / 앱을 닫아도 유지 / 일정 시간 뒤 초기화.
