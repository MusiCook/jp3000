# 회차 학습 시스템

한 단계를 세 번 돌면서 가리는 쪽을 바꿔 가는 구조.
회차를 마칠 때마다 단계 위의 왕관에 별이 하나씩 찬다.

이 문서는 **왜 그렇게 만들었는지**와 **어디를 고치면 되는지**를 적는다.
바뀐 내역만 보려면 `CHANGELOG.md` 를 본다.

---

## 1. 어떻게 도는가

| 회차 | 가리는 쪽 | 하는 일 |
|---|---|---|
| 1회차 | 한국어 | 일본어를 보고 뜻을 고른다 (읽기) |
| 2회차 | 번갈아 | 한 문장 안에서 좌우를 교차해 가린다 |
| 3회차 | 일본어 | 한국어를 보고 일본어를 고른다 (산출) |

**단계 이동은 막지 않는다.** 별은 순수하게 표시일 뿐,
별 세 개를 채워야 다음 단계로 갈 수 있는 것은 아니다.
완전히 익히고 넘어가고 싶게 만드는 장치이지 관문이 아니다.

문장의 가린 자리를 다 맞히면 그 문장이 **자동으로 완료**된다.
손으로 완료를 체크하던 것(왼쪽으로 밀기)은 없앴다.
단계 50문장을 다 채우면 별이 하나 붙고 다음 회차로 넘어간다.

## 2. 2회차 교차 — 짝이 맞아야 성립한다

```
1회차   私は  韓国人  です      |  [■]  [■]   [■]
2회차   [■]  韓国人  [■]      |  저는  [■]  입니다      ← 교차
3회차   [■]  [■]   [■]      |  저는  한국인  입니다
```

한 덩어리에서 **일본어와 한국어 중 한쪽만** 가린다.
그래야 반대쪽이 단서로 남아 풀 수가 있다.

그런데 이게 성립하려면 **좌우 덩어리 수가 같아야** 한다.
수가 다르면 몇 번째끼리 짝인지 알 수 없고,
잘못 짝지으면 가린 자리의 단서까지 같이 가려 버린다.

```
05-012   かばんに / 本が / あります      일본어 3덩어리
        가방에 / 책이 / 있습니다        한국어 3덩어리   → 교차한다

18-009  ここは / 危険です              일본어 2덩어리
        여기는 / 위험 / 합니다         한국어 3덩어리   → 한쪽만 통짜로 가린다
```

현재 **1,550문장 중 1,471문장(94.9%)** 이 짝이 맞는다.
나머지 79문장은 그 문장만 한쪽을 통짜로 가린다.

어느 쪽부터 가릴지는 **문장 번호를 씨앗으로** 정한다.
새로 열 때마다 바뀌면 풀던 회차가 어그러지기 때문이다.

관련 함수 — `maskPlan(s)` 가 `{j(i), k(i)}` 두 함수를 돌려준다.
`i` 는 부호를 뺀 자리 번호라 좌우가 서로 맞는다.

## 3. 덩어리 나누기 — 여기서 두 번 데였다

교차는 덩어리 나누기 위에 서 있다. 그래서 먼저 규칙을 고쳤다.
**84.3% → 94.9%.**

### 단위와 명사가 같은 글자일 때

```
전   かばんに本が / あります        공원에 개가 / 있습니다
후   かばんに / 本が / あります     공원에 / 개가 / 있습니다
```

`SUFJP` 는 「3本」의 **단위**를 앞말에 붙이려고 만든 목록인데,
앞에 무엇이 오든 글자만 보고 붙였다. 「本」(책)도 걸렸다.
한국어 `SUFKO` 의 「개」도 똑같이 「공원에 **개**가」에서 걸렸다.

이제 **앞말이 숫자일 때만** 붙인다 (`sufJPok`, `sufKOok`).
숫자와 무관한 것은 따로 뺐다 — 이름 뒤의 さん·씨, 지명 뒤의 行き·행, 시각 뒤의 半·반.

### て + 보조동사

```
14-005   ゆっくり / 話していただけますか      일본어 2덩어리
         천천히 / 말해 / 주시겠습니까        한국어 3덩어리
```

`GLUEJP` 목록의 주석은 **「한국어 해석에서도 앞말과 한 덩어리가 되는 것만 넣는다」**
라고 적혀 있었는데, ています·ていただけますか 계열 13개가 그 규칙을 어기고 들어와 있었다.
빼니 164문장이 한 번에 맞았다. 퀴즈 단위도 나아졌다 —
「話していただけますか」 통째를 4지선다로 고르는 것보다 낫다.

### 남은 79문장

```
18-009   危険です      /  위험 / 합니다      な형용사+です 를 붙여 쓴 곳과 뗀 곳이 섞여 있다
24-001   行ったことが   /  간 / 적이         こと 처리
08-029    一万円       /  만 엔             한국어가 「일」을 생략
```

**규칙이 아니라 문장 데이터 문제**라 전수 검토로 미뤘다.
숫자끼리 붙이는 규칙도 검토했지만, 08-029(一万円/만 엔)는 맞아도
08-027(五百円/오 백 엔)이 깨져서 넣지 않았다.

> **주의** — 덩어리 나누기를 바꾸면 `QDONE` 의 열쇠(덩어리 번호)가 밀린다.
> 기존 퀴즈 기록이 엉뚱한 자리를 가리키게 된다.
> 규칙을 손볼 일이 생기면 저장 구조 변경과 **같은 작업에 묶어야** 한다.

## 4. 저장 구조

### 맞힌 자리 — 회차를 비트로

```
QDONE["1-35-k0"] = 1     1회차에서 맞힘
                 = 3     1·2회차
                 = 7     세 회차 모두
```

열쇠는 `단계-문장번호-쪽+덩어리번호` 다. `k` 는 한국어, `j` 는 일본어.

회차별로 열쇠를 따로 두는 대신 **값을 비트로** 썼다.
열쇠 개수가 늘지 않고, 옛 기록은 값이 모두 `1` 이라 그대로 1회차 기록으로 읽힌다.

이게 없으면 2회차에서 랜덤하게 푼 일본어 자리가 3회차를 미리 뚫어 놓는다.
3회차가 시작도 전에 절반쯤 열린 채로 시작된다.

읽고 쓰는 곳 — `isSolved(key, r)`, `markSolved(key, r)`, `rbit(r)`.

### 진도

```js
ST = {
  v: 3,
  lv: 4,                                  // 보고 있는 단계
  pg: 0,                                  // 25문장씩 나눈 쪽
  r:    { 4: 2 },                         // 그 단계가 도는 회차
  done: { 1:{4:[1,2,3]}, 2:{}, 3:{} },    // 회차별 완료 문장
  star: { 4: 1 },                         // 얻은 별
  bm:   { 4: 12 }                         // 북마크
}
```

**별은 계산으로 뽑지 않고 따로 저장한다.**
「다시 풀기」로 `QDONE` 을 지워도 별은 남아야 하기 때문이다.

`done` 도 계산으로 뽑지 않는다.
옛 판에서 손으로 밀어 완료한 문장은 퀴즈 기록이 없어서,
계산으로 뽑으면 그동안의 진도가 통째로 사라진다.

읽는 곳 — `curR(lv)`, `doneList(lv, r)`.

### 회차 넘기기

`rollRound(lv)` 가 단계를 다 채웠는지 보고 별을 주고 회차를 올린다.
마친 회차 번호를 돌려주고, 아직이면 0.

퀴즈를 맞힐 때만이 아니라 **`build()` 첫머리에서도** 부른다.
옛 진도를 옮겨 온 단계가 여기서 넘어간다.

## 5. 옮기기 코드

```
진도    J3|단계|1회차완료|2회차완료|3회차완료|북마크|별|회차
퀴즈    Q2|통계|맞힌자리
```

- 완료 문장은 이어진 번호를 `1-5` 로 줄인다 (`encDone`)
- 맞힌 자리는 값이 `1` 이면 생략하고, 아니면 `1-35-k0~3` 으로 붙인다
- **옛 `J2`·`Q1` 코드도 읽는다.** 회차가 없던 시절 것이므로 1회차 진도로 넣고,
  다 끝낸 단계에는 별 하나를 준다
- 반대로 **새 코드는 업데이트 안 된 기기에서 못 읽는다.** 기기를 두 대 쓰면 양쪽을 같이 올려야 한다

기기 간 자동 동기화는 로그인과 DB가 필요해서 정식 배포를 준비할 때 다시 본다.

## 6. 별 — 왕관

```
별 1개   ★ ☆ ☆        별 2개   ★ ☆ ★        별 3개   ★ ★ ★
```

채우는 차례는 **왼쪽 → 오른쪽 → 가운데** (`STORDER = [1,3,2]`).
가운데가 가장 높이 솟아 있어서, 마지막에 채워야 왕관이 완성돼 보인다.

### 걸렸던 것

**가로 내비는 위로 삐져나온 것이 잘린다.** `.levels` 에 `overflow-x:auto` 가 걸려 있는데,
CSS 규칙상 가로 넘침을 자르면 세로 넘침도 같이 잘린다.
그래서 `.levels` 의 **위쪽 여백을 16px 로** 늘려 그 안쪽에 별을 그린다.
여백을 건드렸으므로 「あ」 단추도 `margin-top` 으로 같이 내려 줄을 맞춰야 한다.

머리띠가 8px 두꺼워졌지만 `.row` 의 `scroll-margin-top:130px` 은 그대로 뒀다.
북마크로 뛸 때 `block:'center'` 로 부르기 때문에 가운데 정렬이 조금 밀릴 뿐,
문장이 머리띠 뒤로 숨지는 않는다. (실측 머리띠 높이 — 폰 155px · 패드 159px · PC 100px)

**유니코드 ★ 는 기기마다 모양이 다르다.** 안드로이드에서는 컬러 이모지로 나오기도 한다.
`ICO.star` 로 SVG를 직접 그린다. 채운 별은 `fill`, 빈 별은 `stroke` 만.

**PC 세로 목록은 한 줄이라** `★☆★` 가 이 빠진 것처럼 보인다.
`order` 로 자리만 바꿔 왼쪽부터 차 보이게 했다. 상태는 같고 보이는 순서만 다르다.

## 7. 회차를 마쳤을 때

```
        ★              큰 별이 튀어오른다
   1회차를 마쳤습니다
      ★ ☆ ☆
   이제 2회차입니다
   일본어와 한국어를 번갈아 가립니다.
    [ 이어서 하기 ]
                       ↓ 닫으면
        별이 위쪽 왕관 자리로 날아가 박힌다
```

| | 어떻게 | 함수 |
|---|---|---|
| 색종이 | 캔버스에 직접 그린다. 조각 90개, 약 2.6초 | `confetti(cx, cy)` |
| 축하음 | 이미 있던 `tone()` 으로 4음 아르페지오 | `fanfare()` |
| 별 날리기 | 팝업의 별을 왕관 자리로 옮긴다 | `celDone()` → `flyStar(a)` |

**색은 앱 팔레트만 쓴다** — 금색·초록·연초록·크림 (`FXC`).
무지개색은 이 앱의 차분한 결과 안 맞는다.

**라이브러리를 쓰지 않는다.** 오프라인 단일 파일 구조를 깨지 않기 위해서다.
늘어난 용량은 6KB.

### 조심할 것

- **팝업이 닫히면 별의 크기를 잴 수 없다.** `celDone()` 이 먼저 재고 나서 닫는다
- **날아오기 전까지 왕관 자리는 비워 둔다** (`data-hold`). 안 그러면
  이미 금색인 자리에 별이 날아가 박히는 이상한 그림이 된다
- **`closeAllPop()` 과 배경 클릭도 축하 팝업을 그냥 닫지 않는다.**
  그냥 닫으면 `data-hold` 가 남아 별이 영영 안 채워진다
- **「움직임 줄이기」** 를 켠 기기에서는 색종이와 날아가는 별을 건너뛰고
  팝업만 조용히 띄운다. 별은 그대로 채워진다 (`reduceMotion()`)

## 8. 보기 모드는 어디로 갔나

눈 아이콘(`#bEye`)을 CSS 한 줄로 감췄다. 코드는 그대로 남아 있다.

무엇을 가릴지는 이제 회차가 정한다.
`MODE === 'all'` 만 「가림 끄기」로 살아 있고, 나머지 값은 뜻을 잃었다.

되살리려면 CSS의 `#bEye{display:none;}` 을 지운다.
그러면 「모두 보기」가 곧 가림 끄기가 된다.
그때 `let MODE='jp';` 로 되돌리는 줄도 같이 지운다 —
단추가 없는 동안 「모두 보기」로 두었던 사람이
가림 없는 화면에 갇히지 않도록 넣어 둔 안전장치다.

## 10. 남은 일

**오답노트를 틀린 형식 그대로 출제하기.**
지금은 한 말을 **두 번** 낸다 — 첫 번째는 뜻을, 두 번째는 일본어를 묻는다.
두 번 다 맞혀야 끝나고, 틀리면 처음으로 돌아가 두 번을 새로 채운다.
양쪽을 다 물으므로 틀린 방향은 반드시 한 번 나오지만, **틀린 방향을
먼저** 내지는 못한다. 그러려면 `QSTAT` 에 어느 방향으로 틀렸는지를
기록해야 한다 — 지금은 `{o, x}` 뿐이고 방향이 없다.
통계 화면은 합계만 쓰므로 그대로 동작한다.

**덩어리 짝 검사기.**
검사기(`node tools/check.js`)가 좌우 덩어리 짝을 못 본다.
덩어리 나누는 코드가 `trainer.html` 안에 있고 검사기는 `src/*.js` 만 읽기 때문이다.
`src/chunk.js` 로 빼내면 앱과 검사기가 같은 코드를 쓰게 되고,
규칙이 두 벌로 갈라지는 것도 막는다.
`tools/quiz-audit.js` 는 가짜 DOM 을 씌워 `trainer.html` 을 통째로
돌리는 길을 택했다. 그 방법도 되지만, 빼낼 수 있는 것은 빼내는 편이
읽기 쉽다 — 보기 만드는 코드는 `src/quiz.js` 로 이미 빼냈다.
`build.py` 가 `<script src>` 를 알아서 합치므로 배포 구조는 그대로다.
**전수 검토 전에 해 두는 것이 좋다.**

**문장 데이터 전수 검토.**
짝이 안 맞는 79문장, 그리고 「私は観光です」처럼
문법은 맞지만 실제로 쓰지 않는 표현.
