# 문서 안내

이 폴더는 **왜 그렇게 만들었는지**를 적어 두는 곳이다.
코드를 읽으면 알 수 있는 것은 적지 않는다. 코드를 읽어도 알 수 없는 것 —
무엇을 고민했고, 무엇을 버렸고, 왜 그 길을 골랐는지 — 만 적는다.

새 대화를 시작할 때 여기부터 읽으면 맥락이 잡힌다.

---

## 무엇이 어디에 있나

| 문서 | 담는 것 | 언제 읽나 |
|---|---|---|
| `APP.md` | 이 앱이 무엇인가. 설계 원칙, 다른 학습앱과의 차이 | 처음 올 때 · 방향을 의심할 때 |
| `PLAN.md` | 작업 규칙, 데이터 형식, 60단계 구성, 검사기 | 문장을 쓰거나 사전을 손댈 때 |
| `ROUNDS.md` | 회차 학습(3회차 가림)의 구조와 함정 | 회차·가림·별을 손댈 때 |
| `NOTES-PLAN.md` | 「더 배워보기」에 무엇을 어떻게 담을지 | 설명을 채울 때 |
| `VOICE.md` | 문장 음성(TTS). 목소리를 어떻게 골랐고 무엇이 안 됐나 | 소리를 손댈 때 |
| `BACKLOG.md` | 남은 일과 개선 요소를 **한 곳에** 모은 것 | 다음에 무엇을 할지 정할 때 |
| `REVIEW.md` | 코드 구조 전수 검토 기록 | 3단계마다 · 구조를 의심할 때 |
| `CHANGELOG.md` | 바뀐 내역. 최근 것이 위 | 「언제 뭐가 바뀌었지」 |

작업 흐름·배포·탈출구(`fix.html`)는 문서가 아니라 루트의 `README.md` 에 있다.
그쪽은 **손이 움직이는 순서**를 적는 곳이고, 이쪽은 **머리가 움직인 자취**를 적는 곳이다.

## 기록 규칙

무엇을 하든 아래 중 하나에는 남긴다. 어디에 적을지 헷갈리면 `CHANGELOG.md` 에
적고 넘어간다 — **안 적는 것보다 엉뚱한 곳에 적는 편이 낫다.**

| 이런 일이 있었으면 | 여기에 적는다 |
|---|---|
| 코드나 데이터를 고쳤다 | `CHANGELOG.md` 맨 위에 한 덩어리 |
| 고치다가 원인이 딴 데 있었다 | `CHANGELOG.md` 에 **원인까지** 적는다 |
| 하려다 안 되는 것을 확인했다 | 그 분야 문서의 「안 되는 것」 칸 |
| 두 길 중 하나를 골랐다 | 그 분야 문서에 **버린 길과 이유**까지 |
| 새로 할 일이 생겼다 | `BACKLOG.md` |
| 할 일을 끝냈다 | `BACKLOG.md` 에서 지우고 `CHANGELOG.md` 로 옮긴다 |
| 새 분야를 시작했다 | 문서를 새로 만들고 이 표에 한 줄 |

### 적는 법

- **실측만 적는다.** 「빠를 것이다」가 아니라 「1.02초에서 0.81초가 됐다」.
  재보지 않았으면 재보지 않았다고 적는다
- **버린 길을 적는다.** 고른 길만 적으면 다음 사람이 같은 길을 또 파본다.
  실제로 그랬다 — 빠르기를 지시문으로 조절하는 일을 두 번 시도했다 (`VOICE.md`)
- **원인을 적는다.** 「고쳤다」가 아니라 「쪽 번호를 안 되돌린 탓이었다」.
  증상만 적힌 기록은 다음에 같은 증상이 났을 때 쓸모가 없다
- **숫자를 적는다.** 몇 개 중 몇 개인지. 「많다」는 반 년 뒤에 아무 뜻이 없다
