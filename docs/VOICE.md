# 문장 음성

문장을 소리로 들려주는 일. 2026-09-10 시작.
지금은 **1단계 50문장을 여자·남자 두 목소리로 구워 둔 상태**이고,
앱에는 아직 붙이지 않았다.

---

## 1. 왜 미리 구워 두는가

브라우저에서 Gemini 를 직접 부르지 않는다. 이유는 둘이다.

- **키를 숨길 데가 없다.** 배포본은 `dist/jp3000.html` 한 장이고 공개돼 있다.
  키를 넣으면 그대로 드러난다
- **오프라인에서 못 쓴다.** 이 앱은 비행기와 해외 로밍에서 되는 것이 값이다

그래서 `tools/tts.js` 로 미리 굽고, 앱은 **파일만 재생한다**.
설명을 빌드 타임에 만들어 넣는 것과 같은 원칙이다 (`APP.md` 원칙 ⑤).

### 지금 앱이 쓰고 있는 것

문장 옆 확성기 단추(`.spk`)는 **브라우저 내장 `speechSynthesis`** 를 쓴다
(`trainer.html` 의 `speak()` · `speakText()`). 공짜고 무게가 0 이지만 한계가 있다.

- **기기마다 목소리가 다르다.** 같은 문장이 폰과 PC 에서 딴사람 소리로 난다
- **일본어 음성이 없으면 아무 소리도 안 난다.** `JAV` 가 비면 단추가 죽는다
- 억양을 손볼 길이 없다. 한자 읽기도 기기에 맡겨야 한다

미리 구운 파일은 이 셋을 다 없앤다. 대신 무게가 붙는다 (5장).
**둘 중 하나를 버릴 필요는 없다** — 파일이 있으면 파일을, 없으면
`speechSynthesis` 를 쓰는 식으로 겹쳐 두면 아직 굽지 않은 단계도 소리가 난다.

| 항목 | 값 | 왜 |

| 모델 | `gemini-3.1-flash-tts-preview` | |

목소리마다 인물 지시(`PERSONA`)를 짝지어 둔다. 지시문의 사람이 목소리 성별과
어긋나면 연기가 흔들린다.

## 3. 안 되는 것 — 빠르기를 지시문으로 조절하기

**두 번 시도했고 두 번 다 실패했다. 다시 하지 말 것.**

Gemini TTS 에는 `rate` 같은 숫자 손잡이가 없다. 빠르기를 바꾸는 길은
프롬프트 한 줄뿐이라, 여섯 단계로 나눠 구워 견줬다
(`1느림 · 1a덜느림 · 1b거의보통 · 2보통 · 3조금빠름 · 4원어민`).

일어난 일:

- **인물이 같이 바뀐다.** 같은 Erinome 인데 지시문을 바꾸면 딴사람 목소리가 났다.
  빠르기만 움직이는 손잡이가 아니다
- **순서가 뒤집힌다.** 어떤 목소리는 「덜 느리게」가 「느리게」보다 **더 느렸다**
- 소리 길이를 재서 나란히 찍어 봐야 이게 보인다. 귀로만 들으면 헤맨다

**결론** — 지시문은 하나로 못 박고, 빠르기는 **재생할 때** `playbackRate` 로 건다.
`preservesPitch` 를 켜면 빨라져도 음정이 올라가지 않는다.
사파리는 이름이 다르던 때가 있어 `webkitPreservesPitch` 도 함께 짚는다.

## 4. 도구 쓰는 법

```bash
node tools/tts.js --models          # 쓸 수 있는 모델
node tools/tts.js 1 1-50            # 1단계 1~50번을 여자·남자 둘 다
node tools/tts.js 1 1-50 --only f   # 여자만
node tools/tts.js 1 1-50 --force    # 이미 있어도 다시
node tools/tts.js --compare         # 목소리 8명 견주기 → compare/compare.html
node tools/tts.js --speed --male    # 빠르기 사다리 → speed/speed.html
```

키는 `.gemini-key` · `API_key.txt` · `.env` 중 하나에 두거나 환경변수 `GEMINI_API_KEY`.
**모두 `.gitignore` 에 들어 있다.** 키는 어떤 경우에도 화면에 찍지 않는다.

만든 것은 `dist/voice/` 에 놓이고 `listen.html` 로 한자리에서 들어 본다 —
문장마다 「여자」·「남자」 단추가 있고, 같은 단추를 다시 누르면 멈춘다.
위쪽 손잡이로 빠르기를 바꿔 볼 수 있다.

이미 있는 파일은 건너뛴다. 실패해도 앞의 것은 남으니 이어서 돌리면 된다.

## 5. 무게 — 아직 풀지 않은 문제

| | 파일 | 무게 |
|---|---|---|
| 1단계 (실측) | 100개 | **14.7MB** |
| 31단계까지 | 3,100개 | 약 460MB |
| 3,000문장 다 차면 | 6,000개 | **약 880MB** |

WAV(16비트 24kHz 모노) 라서 그렇다. 이대로는 저장소에도 배포에도 못 올린다.
GitHub Pages 는 저장소 1GB 를 권고 한도로 본다.

그래서 지금은 `dist/voice/` 를 **`.gitignore` 에 넣어 저장소 밖에 둔다.**
앱에 붙이기 전에 반드시 정해야 할 것:

- **포맷** — Opus 나 MP3 로 줄이면 1/8~1/10 이 된다. 880MB → 90~110MB
- **어디에 둘 것인가** — 저장소에 함께 둘지, 따로 둘지
- **오프라인** — 서비스 워커가 소리까지 담을 것인가. 담으면 첫 설치가 무겁다.
  단계별로 나눠 받는 길이 있다
- **한 문장에 두 목소리를 다 둘 것인가** — 무게가 두 배다. 한쪽만 둘지, 고르게 할지
