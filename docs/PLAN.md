# 일본어 3000 — 작업 문서

일본 여행에서 읽고 말할 수 있는 수준을 목표로, 3,000문장을 60단계로 나눠 만드는 학습지.
학습 기간 약 2년. 문법을 외우지 않고 문장을 계속 읽어 나가며 자연스럽게 익히는 것이 원칙.

---

## 1. 현황

| 항목 | 값 |
|---|---|
| 완성 단계 | 31 / 60 |
| 완성 문장 | 1,550 / 3,000 (52%) |
| 사전 등재 | 1,570여 개 |
| 의미 그룹 | 36개 |
| 가타카나 | 기본 76자 중 73자 사용 (미사용 ヲ ヂ ヅ — 현대 일본어에서 거의 안 쓰임) |

## 3. 데이터 형식

### words.js

```js
"tabemasu": {
  t: "{食|た}べます",   // 표기. {한자|읽기}로 감싸면 후리가나가 붙는다
  p: "v",               // 품사
  m: "먹다",            // 뜻
  y: "わ",              // (선택) 발음 교정. 조사 は→わ, へ→え 등
  adj: "i",             // (형용사만) 종류
  f: [ ... ]            // (선택) 툴팁
}
```

**품사 코드 `p`**

| 코드 | 뜻 | 화면 색 |
|---|---|---|
| `n` | 명사·대명사·수사 | 파랑 |
| `v` | 동사 | 빨강 |
| `a` | 형용사 | 빨강 |
| `c` | 서술 (です·ます·ください 등) | 빨강 |
| `p` | 조사 | 회색 |
| `d` | 부사 | 먹색 |
| `x` | 그 밖 (연체사·접속사·감탄) | 먹색 |

**형용사 종류 `adj`** — 검사기가 활용 오류를 잡는 데 쓴다. 형용사에는 반드시 넣어야 한다.

| 값 | 뜻 | 예 |
|---|---|---|
| `i` | い형용사 원형 | 安い |
| `iku` | い형용사 く형 | 安く |
| `ita` | い형용사 과거 | 安かった |
| `na` | な형용사 | 静か |
| `nana` | な형용사 な형 | 静かな |

**툴팁 `f`**

```js
f: [{ g: "그룹명", items: [[라벨, 일본어, 설명]] }]
```

- 첫 그룹이 `"형태"`이면 화면에 **실선** 밑줄, 아니면 **점선** 밑줄
- 항목은 반드시 3개 요소. 설명이 없으면 빈 문자열

**그룹 순서 표준**

| 품사 | 순서 |
|---|---|
| 형용사 | 형태 → 반대말 → 뜻 구분 |
| 동사 | 형태 → 뜻 구분 → 짝이 되는 말 |
| 명사 | 짝 → 참고 |
| 조사 | 쓰임 → 참고 |

**반대말 규칙**

- 반대말이 둘이면 둘 다 적고 어느 뜻일 때인지 밝힌다 (`高い` → `安い`(값) / `低い`(높이))
- 품사가 달라도 그대로 적는다 (`静か`(な) ↔ `うるさい`(い))
- 딱 떨어지는 짝이 없으면 비워둔다. 억지로 채우지 않는다

### sentences-01.js

```js
SENT[1] = {
  title: "인사와 자기소개",
  memo: "단계 설명",
  s: [
    { n: 1,                              // 고정 번호. 절대 바꾸지 않는다
      j: ["watashi","wa","kimu","desu","。"],   // 일본어 토큰 (words.js 키)
      k: [["저","n"],["는","p"],[" 김","n"],["입니다","c"]],  // 한국어 해석
      t: "설명줄" }                      // (선택)
  ]
};
```

**`n` (고정 번호)**
진도 저장이 이 번호를 기준으로 한다. 문장을 지워도 그 번호는 결번으로 남기고, 새 문장은 항상 뒤 번호를 받는다. 순서를 바꿔도 체크가 밀리지 않는다.

**`j` (일본어)**
- words.js에 없는 문자(`。` `、` 등)는 그대로 출력된다
- 토큰 순서가 곧 화면 표시 순서

**`k` (한국어)**
- **띄어쓰기는 글자 앞의 공백으로 직접 표시한다** (`" 이름"`). 자동 처리하지 않는다
- 일본어 토큰과 1:1로 대응할 필요 없다. 한국어에서 뭉치면 뭉쳐 쓴다
- 일본어 `、`를 한국어에 그대로 옮기지 않는다. 한국어에서 쉼표를 쓰지 않는 자리면 뺀다

## 4. 작성 규칙

### 배치 단위

| 항목 | 값 |
|---|---|
| 한 배치 | 25문장 |
| 한 단계 | 50문장 = 2배치 |
| 전체 | 60단계 = 120배치 = 3,000문장 |

### 배치당 신출 단어

- **15개**를 넘기지 않는다. 나머지는 기존 단어를 재사용한다
- 그중 **최소 5개는 가타카나**로 배정한다 (간판·안내문 대응)
  - 76자를 거의 다 채운 지금은 이 규칙을 완화하고, 상황에 자연스러운 만큼만 넣는다
- **동사 활용형은 신출로 세지 않는다.** `食べます`를 넣었으면 `食べません`·`食べた`·`食べて`는 같은 단어다
- 복습 단계(11·12·23·24·35·36·47·48)는 신출을 0~2개로 억제하고 회수에 쓴다

### 문장 원칙

- **해당 단계까지 나온 문법만 쓴다.** 미래 문형 선행 금지
- **틀린 문장을 교재에 싣지 않는다.** 대조를 위해서도 안 된다. 틀린 형태는 설명줄이나 툴팁으로만 언급
- **해석은 자연스러운 한국어를 우선한다.** 직역이 어색하면 의역하고, 직역을 설명줄에 남긴다
- 같은 문형을 반복하되 어휘와 상황을 바꿔 지루하지 않게 한다
- 묻고 답하는 짝을 붙여 배치하면 흐름이 산다

### 한국어 해석에서 주의할 것

| 상황 | 처리 |
|---|---|
| 「私の」 | "저의"가 아니라 "제" |
| 「仕事です」 | "일입니다"가 아니라 "근무입니다" |
| 일본어 `、` | 한국어에서 어색하면 뺀다 |
| 한 줄에 문장 두 개 | 한국어에도 마침표를 넣는다 |

## 5. 검사기 (check.js)

배치를 추가한 뒤 **반드시** 돌린다.

### 검사 항목

| 항목 | 내용 |
|---|---|
| 키 중복 선언 | 같은 키를 두 번 등록했는지 |
| 키 충돌 | 동사 생성기가 기존 항목을 덮어쓰는지 |
| 미정의 단어 | 문장이 사전에 없는 키를 가리키는지 |
| 완전 중복 | 같은 일본어 문장이 두 번 나오는지 |
| 해석 누락 | `k`가 비었는지 |
| 형용사 활용 | い/な 부정형·과거형 오용 |
| あまり | 부정 없이 쓰였는지 |
| 가타카나 진도 | 기본 76자 중 몇 자를 썼는지 |
| 문형 분포 | 조사+서술 조합의 편중 |

### 키 충돌 — 가장 위험한 오류

같은 로마자 키를 두 번 쓰면 **뒤에 등록한 것이 앞의 것을 조용히 덮어씁니다.** 화면에는 엉뚱한 글자가 나오지만 오류는 안 납니다.

실제로 발생했던 사례입니다.

| 나중 | 덮어쓴 것 | 결과 |
|---|---|---|
| `sumimasen` (住みません) | `すみません` | 「죄송합니다」가 「살지 않습니다」로 |
| `san` (三) | `さん` | 「田中さん」이 「田中三」으로 |
| `kinen` (記念) | `禁煙` | 금연이 기념으로 |
| `soba` (메밀국수) | `そば`(곁) | 「駅のそば」가 국수집으로 |

**대책** — 이미 있는 키인지 먼저 확인한다. 겹치면 뒤에 `2`나 다른 접미를 붙인다 (`san3`, `soba2`, `kinen2`, `sumu`).

### 검사기도 틀릴 수 있다

31-049에서 「よかった + ら」를 오류로 잡은 적이 있습니다. 문장이 맞고 규칙이 틀린 경우였습니다.
**경고가 뜨면 문장을 먼저 의심하되, 문장이 맞다면 규칙을 의심한다.**

### 기계가 못 잡는 것

- 문법은 맞지만 원어민이 안 쓰는 표현
- 어색한 한국어 번역
- 상황에 맞지 않는 어휘

→ **매 배치마다 일본어·한국어 대조표를 눈으로 훑는다.** 이것이 유일한 방법입니다.

## 6. 3단계마다 전수 검토

3단계 구간이 끝날 때마다(3·6·9·12·…) 직전 구간을 전수 점검한다.

**점검 항목**

1. 해석·형식 — 구두점, 띄어쓰기, 의문형 대응, 쉼표 과다
2. 사전 구조 — 필수 항목, 형용사 종류 표시, 후리가나 괄호 짝
3. 표기 중복 — 같은 일본어가 두 항목으로 등록됐는지
4. 어휘 반복 — 1회만 등장하는 단어 수
5. 분야 분포 — 특정 상황에 쏠렸는지
6. 문장 길이 — 단계별 추이
7. 동사 형태 분포 — ます / ました / ません / て형 균형

**어휘 반복 지표 읽는 법**

전체 수치는 동사 활용형이 섞여 왜곡된다. **동사를 제외한 수치**가 실제 어휘 반복을 나타낸다.
복습 단계에서 20% 아래로 내리는 것이 목표.

| 기능 | 설명 |

| 옮기기 | 진도와 퀴즈 기록을 각각 짧은 코드로 뽑아 다른 기기에 붙여넣기 |
| 효과음 | 종·물방울·나무·화음·없음. 파일 없이 브라우저가 합성 |
| 발음 | 기기에 깔린 일본어 음성 중에서 고른다. 고품질 음성을 먼저 잡는다 |
| 앱 설치 | 홈 화면에 추가하면 주소창 없이 뜨고 오프라인에서도 열린다 |
| 화면 대응 | 폰 / 패드(글자·여백 확대) / PC(왼쪽 세로 단계 목록, 키보드) |
| 초기화 | 설정 맨 아래. 경고를 한 번 더 띄운다 |

### 키보드 (PC)

```
← →     단계 이동
[ ]     쪽 이동
1~4     보기 고르기
ESC     팝업 닫기
```

### 알아둘 제약

- **파일 앱·메신저 미리보기로 열면 작동하지 않는다.** 스크립트가 차단된다
- 발음은 기기에 일본어 음성이 있어야 나온다. 아이폰은 받은 음성을 웹에 다 열어주지 않을 때가 있다
- 고저 악센트는 신뢰하지 말 것. 橋/箸처럼 억양으로 갈리는 단어는 기계 음성이 자주 틀린다
- 진도는 기기별로 따로 저장된다. 옮길 때는 설정의 코드를 쓴다
- 효과음은 화면을 한 번 건드린 뒤부터 난다 (아이폰 제약)

manifest.webmanifest
sw.js
icon-192.png  icon-512.png  icon-maskable-512.png  apple-touch-icon.png

저장소 `MusiCook/jp3000` (Public), Pages는 `main` / `(root)` 로 설정되어 있다.
프로젝트 전체가 그대로 올라가 있으므로 `dist`는 저장소 안의 한 폴더다.

```bash
git add -A

git push
```

```
https://musicook.github.io/jp3000/dist/jp3000.html
```

- **서비스 워커는 HTTPS에서만 동작한다.** GitHub Pages면 된다
- **`sw.js`의 캐시 이름을 올리지 않으면** 브라우저가 옛 파일을 계속 쓴다. 배포 전 확인
- 파일을 새로 올리면 앱이 자동으로 받아두고 「새 내용이 있습니다」를 띄운다
- 홈 화면에 추가: 아이폰은 Safari 공유 → 홈 화면에 추가, 안드로이드·PC는 주소창 설치 아이콘

## 10. 남은 과제

**진행 중**

- 32~60단계 문장 작성 (1,450문장)
- 「더 배워보기」 설명 채우기 — `NOTES-PLAN.md` 참고

**완성 후 검토할 것**

- 원어민 검수 — AI가 만든 문장 중 일부는 문법이 맞아도 실제로 쓰지 않는 표현일 수 있다. 표본 점검 필요
- 진도 자동 동기화 — 지금은 코드 복사. 서버(Cloudflare Worker 등)를 붙여야 한다
- 파일 분리 — 3,000문장이 차서 1MB를 넘으면 `notes.js` 등으로 나눈다
- 부분 렌더링 — 지금은 단계를 옮길 때마다 25문장을 다시 그린다. 느려지면 손본다

**의도적으로 넣지 않은 것**

- 단어장 — 문장에서 떼어낸 단어 암기는 이 교재의 원칙과 어긋난다. 「가림」과 오답노트로 대체
- 런타임 AI 호출 — 정적 파일 배포라 API 키를 숨길 곳이 없고, 오프라인에서 못 쓴다.
  설명·검수는 빌드 타임에 미리 만들어 넣는다

## 11. 겪은 사고와 교훈

**사전 키 충돌 (4건)** — 같은 로마자 키를 두 번 쓰면 뒤의 것이 앞의 것을 조용히
덮어쓴다. 화면에는 엉뚱한 글자가 나오지만 오류는 없다. 검사기에 넣어 자동으로
잡는다.

**정규식으로 큰 구간 치환하다 함수 여럿 삭제** — 범위를 잘못 잡아 `build`,
`paint`, 이벤트 처리가 통째로 사라졌다. 사본도 같은 상태였다.
**큰 구간은 정확한 문자열로 다루고, 고친 뒤 반드시 렌더링을 확인한다.**

**CSS만 지워지고 마크업이 남음** — 「해석 보기」 버튼이 기본 스타일로 크게
나왔다. 스크립트가 중간에 실패해 일부만 적용된 경우다.
**변경을 한 덩어리로 묶지 말고 나눠 적용한다.**

**검사기도 틀린다** — 「よかった + ら」를 오류로 잡은 적이 있다. 문장이 맞고
규칙이 틀린 경우였다. 경고가 뜨면 문장을 먼저 의심하되, 문장이 맞다면 규칙을
의심한다.
